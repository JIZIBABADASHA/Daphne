# N23 環形緩衝與送料

`core/include/daphne/engine/ring_buffer.h`、`core/include/daphne/engine/ring_feeder.h`、`core/src/ring_feeder.cpp`

## 環形緩衝（`ByteRing`）

播放執行緒與裝置回呼（WASAPI 的 render 執行緒、ASIO 的 bufferSwitch）之間的單一生產者 / 單一消費者無鎖位元組環：

- 容量取 2 的冪（位置用遮罩運算）。讀寫位置是兩個各自占一條快取行的原子變數（`alignas(64)`），避免 false sharing。
- 生產者用 release 寫入、消費者用 acquire 讀取；裝置端只讀，從不阻塞、略過或倒退。
- 內容已經是裝置格式的位元組（N22 / N20 轉換過），回呼裡只做複製。
- 大小約 0.5 秒（`frame_rate × block_align / 2`）。主程式不需要另外設定緩衝大小。

## 送料（`RingFeeder`）

裝置回呼這一側：把環裡的資料填進裝置緩衝區，並處理必須跟著裝置節奏發生的事。

| 情況 | 行為 |
|---|---|
| 暫停 / 繼續 | 裝置繼續運轉，排隊中的音訊留在環裡，所以暫停是立即的、位置是精確的。PCM 以 20 ms 升餘弦淡出 / 淡入；DSD 不淡：原生 DSD 送 DSD 靜音（0x69），DoP 送延續標記序列的 DoP 靜音，DAC 一直鎖在 DSD 模式 |
| 繼續時的 DoP 標記 | 搜尋之後環裡是新的一段串流，所以直接看下一個真實 frame 的標記；若與最後一個靜音 frame 相同，先多插一個靜音 frame，交替不中斷 |
| underrun | PCM 補 0；原生 DSD 補 0x69；DoP（串流結束前）補 DoP 靜音。串流結束時刻意以 PCM 靜音收尾，讓 DAC 離開 DSD 模式 |
| 只取完整 frame | 生產者可能只寫了半個 frame，讀取量一律截到 frame 的整數倍 |
| 電平表 | 實際聽到的內容（PCM）的峰值，前兩個聲道，讀取時歸零（原子 CAS 更新） |

設定介面（暫停、DoP、電平）都是原子變數，可以從任何執行緒呼叫，其餘只在裝置執行緒執行。

## 驗證

實機（`verify/live.py` 第 4 節，VB Hi-Fi Cable、WASAPI 獨占 176.4 kHz、DSD64 DoP）：

- 播放中依序暫停、繼續、搜尋到 1 s、暫停、暫停中搜尋到 0.5 s、繼續。
- 前導靜音之後，DoP 標記在 11.1 秒內不間斷地交替，左右標記一致，underrun 0。

前導靜音（100 ms）期間，虛擬線材在串流啟動時偶爾會掉約 15 ms。這段靜音本來就是為此保留（實際 DAC 上是鎖定時間），所以檢查從前導之後開始。
