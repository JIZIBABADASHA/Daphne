# N15 音量與增益

`dsp/include/daphne/dsp/gain.h`、`dsp/src/gain.cpp`

## 增益級

處理鏈中只有一個增益級，位置在降混之後、交叉饋送與 EQ 之前（原取樣率）：

```
gain_db = (volume.mode == digital ? volume.db : 0) + headroom_db
```

| 設定 | 說明 |
|---|---|
| `volume.mode = digital` | 軟體音量，−120 … 0 dB |
| `volume.mode = hardware` | 裝置端點音量（N24），增益級不動 |
| `volume.mode = fixed` | 不調音量 |
| `headroom_db` | 每軌增益（ReplayGain），−24 … +24 dB。由主程式計算：tag 增益 + 前級，只在 peak tag 允許的範圍內提高；沒有 peak tag 時最多到 0 dB |

- 0 dB 時是逐位元 identity（直接複製）；處理鏈其他級也都 identity 且來源位元深度放得進裝置時，最後的量化級會被省略，整條路徑 bit-perfect（N21）。
- 提高增益可能讓峰值超過 1.0：處理鏈是 float64，峰值保留到最終量化級。
- DSD 直送沒有增益級（N20）。
- 無縫播放時，下一軌的 headroom 在它第一個樣本被解碼的位置生效（N4），所以同一張專輯的每一軌都用自己的增益。

## 漸變

- `set_db()` 可以從任何執行緒呼叫：無鎖的 `std::atomic<double>` 寫入，`process()` 在下一次呼叫開頭讀取。播放執行緒不會被鎖住。
- `prepare()` / `reset()` 之後第一次處理直接用目標值，不淡入。
- 之後每次改變，以振幅線性漸變 `ramp_ms`（預設 20 ms）：
  - 步長在目標改變時算一次 `(target − current) / (ramp_ms · fs)`，每個 frame 加同一個步長，與區塊大小無關。
  - 到達或越過目標就設成目標值，所以回到 0 dB 後又是逐位元 identity。
  - 漸變途中目標再改變時，從目前的值重新起算。
- 效能：
  - `pow` 只在設定改變時計算。
  - 漸變結束後，區塊的剩餘部分以單純乘法處理，不做逐 frame 判斷。

## 驗證（`tests/test_gain.cpp`）

| 測試 | 結果 |
|---|---|
| 0 dB：輸出與輸入逐位元相同，`is_identity()` | 通過 |
| 0 → −20 dB、漸變 10 ms（480 frames）：起點接近原增益、第 479 個 frame 到目標、之後每個樣本 = 輸入 × 目標、單調無過衝 | 通過 |
| 一次處理 4410 frames 與每次 100 frames：逐位元相同 | 通過 |
| 再以每次 64 frames 回到 0 dB：`is_identity()` 為真，之後的輸出與輸入逐位元相同 | 通過 |
| 建構時 −6 dB：第一個樣本直接是目標增益；+6 dB 提高正確 | 通過 |
| 另一個執行緒持續改變增益（0 … −39 dB）時處理 2000 個區塊：每個輸出都在合理範圍內 | 通過 |
