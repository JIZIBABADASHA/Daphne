# N0 專案結構

## 目錄

| 路徑 | 內容 |
|---|---|
| `dsp/` | `daphne_dsp` 靜態庫：訊號處理區塊、濾波器設計、雙倍精度（double-double）運算、平行化工具 |
| `core/` | `daphne_engine` 靜態庫：解碼器、處理鏈、裝置輸出、播放器 |
| `capi/` | `daphne_core` 共享庫（C API，函式前綴 `dc_*`，標頭 `capi/daphne_core.h`） |
| `cli/` | `daphne.exe` 命令列工具（播放、轉檔、量測用） |
| `tests/` | `daphne_tests`（Catch2 單元測試） |
| `verify/` | Python 驗證腳本（需要 numpy、soundfile、ffmpeg 在 PATH）；`live.py` 另需 sounddevice 與 VB Hi-Fi Cable |
| `tools/` | `sdm_design.py`：DSD 調變器係數設計（需要 python-deltasigma、numba） |
| `third_party/` | dr_libs、minimp3、Catch2、FFmpeg（共享開發包）、ASIO SDK |
| `scripts/` | `build.cmd`（Release 建置 + 單元測試）、`fetch_ffmpeg.ps1`、`fetch_asiosdk.ps1` |

## 訊號流程（N1–N24）

圖例：

- `|`、`v`、`-`、`+`：訊號路徑；`+` 是分岔或匯合點。
- `<..` / `..>`：N7 / N8 提供濾波器係數，不在訊號路徑上。
- 最右邊的直線：DSD 檔直送，不經任何處理，直接進 N20。
- `source rate` 括起的三級在來源取樣率執行，兩種核心相同。

N4（播放整合）是整條流程的外框：在 N6 決定核心與裝置格式、建立處理鏈、執行無縫換軌與設定變更，並在處理執行緒上把每個區塊從 N1 推到 N23。N9–N14 未使用（編號保留）。

## 命名

- 命名空間：`daphne`（引擎）、`daphne::dsp`（訊號處理）。
- include 路徑：`daphne/engine/...`、`daphne/dsp/...`。
- 編譯巨集：`DAPHNE_HAVE_FFMPEG`、`DAPHNE_HAVE_ASIO`，由 `core/CMakeLists.txt` 偵測 `third_party/` 是否有對應套件後定義。
- 第三方 include 透過 INTERFACE target `daphne_vendor` 提供。

## 建置

```
scripts\build.cmd
```

- C++20，MSVC，x64，`/W4`，Unicode。
- 輸出在 `build/bin/Release/`；FFmpeg DLL 於建置後自動複製到執行檔旁。
- 命令列程式與測試都以 `wmain` 進入（`/ENTRY:wmainCRTStartup`），路徑一律以 UTF-16 處理。
- FFmpeg 沒有放進 `third_party/ffmpeg` 時仍可建置，但只剩 WAV / AIFF / FLAC / MP3 / DSD。

## 驗證流程

每個節點完成後：

1. `scripts\build.cmd`：建置 + 單元測試，不可有警告。
2. `python verify\<節點>.py`：對實際檔案或訊號做端到端量測（`decoders.py`、`filter_design.py`、`dsd_files.py`、`live.py`）。
3. 結果寫進對應的 `doc/NX_*.md`。
