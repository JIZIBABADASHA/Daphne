# N1 檔案分派

`open_decoder(path, error)`（`core/src/decoder_factory.cpp`）依副檔名挑選解碼器：

| 副檔名（不分大小寫） | 解碼器 |
|---|---|
| wav, wave, bwf, aiff, aif, aifc | dr_wav（N2） |
| flac, fla | dr_flac（N2） |
| mp3, mp2, mp1 | minimp3，浮點輸出（N2） |
| dsf, dff | DSD 轉 PCM（N3）；播放器能直送 DSD 時改走直送 |
| 其他一切 | FFmpeg，由內容探測格式 |

## 規則

- **沒有白名單**：不認得的副檔名一律交給 FFmpeg，因此 TTA、TAK、APE、WavPack、WMA、MKA、CAF、OGA、影片容器內的音軌等全部可播。真正不是音訊的檔案由 FFmpeg 拒絕並回傳錯誤。
- **退回 FFmpeg**：專用解碼器開不了時（少見的 WAV 編碼、FLAC 資料卻命名為 `.wav` 等），再用 FFmpeg 試一次；成功就用 FFmpeg 的結果。DSD 檔不退回（FFmpeg 的 DSD 解碼是另一條路，品質與規格不同）。
- 兩者都失敗時，回傳的錯誤訊息是專用解碼器的（比較能說明檔案哪裡有問題）。
- 副檔名的判定只看最後一個路徑分隔符之後的 `.`，資料夾名稱中的點不會被誤判。

## 介面

```cpp
struct AudioInfo {
    int rate, channels;
    int bits;               // 整數 PCM 的來源位元深度；0 = 浮點或有損
    bool lossless_int;      // 樣本是 bits 位元的精確整數
    int64_t frames;         // -1 = 未知
    uint32_t channel_mask;  // WAVEFORMATEXTENSIBLE 喇叭遮罩，0 = 未知
    std::string codec;
    int dsd_rate;           // DSD 直送時的 DSD 取樣率
    bool dsd_pcm;           // DSD 轉 PCM
};
```

所有解碼器輸出交錯的 float64，±1.0 為滿刻度。整數來源以 `sample / 2^31`（左對齊）正規化，所以只要輸出位元深度 ≥ 來源位元深度，`x · 2^(N-1)` 就能精確還原樣本：檔案到裝置之間不經處理時是 bit-perfect。

## 驗證（`verify/decoders.py` 第 3、4 節）

| 項目 | 結果 |
|---|---|
| TTA、ALAC (M4A)、FLAC in MKA、FLAC in OGA、WavPack | 與來源逐樣本相同 |
| ALAC in CAF | 解碼部分逐樣本相同；尾端少 1912 frames，FFmpeg 自身的解碼器也一樣（CAF 解多工器的限制） |
| WMA v2 | 88064 / 88200 frames（ASF 不儲存精確長度，長度以 FFmpeg 為準） |
| FLAC 資料命名為 `.wav` | 經退回 FFmpeg 解碼，逐樣本相同 |
| 非音訊 `.xyz` | 拒絕，`FFmpeg: cannot open file` |
| 單元測試 | 不可讀的檔案回傳非空錯誤訊息 |
